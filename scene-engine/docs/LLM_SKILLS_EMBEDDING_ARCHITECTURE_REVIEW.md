### 2.2 关键接口定义

#### 2.2.1 LLM运行时上下文组装器

```java
/**
 * LLM运行时上下文组装器
 * 负责整合所有上下文信息，组装成完整的LLM运行时上下文
 */
public interface LlmRuntimeContextAssembler {
    
    /**
     * 组装LLM运行时上下文
     * 
     * 组装流程：
     * 1. 获取Skill包
     * 2. 加载角色上下文 (RoleContext)
     * 3. 加载知识库上下文 (KnowledgeContext) ← 从RAG获取
     * 4. 加载函数定义上下文 (FunctionContext) ← 从Skills获取
     * 5. 加载记忆上下文 (MemoryContext)
     * 6. 组装SystemPrompt
     * 7. 组装Tools
     * 8. 组装Messages
     */
    CompletableFuture<LlmSceneContext> assemble(AssemblyRequest request);
}

/**
 * 组装请求
 */
public class AssemblyRequest {
    private String skillId;           // Skill标识
    private String roleId;            // 角色标识
    private String sessionId;         // 会话标识
    private KnowledgeLoadLevel knowledgeLevel;  // 知识加载级别
    private List<String> knowledgeBaseIds;      // 额外知识库ID
    private Map<String, Object> contextParams;  // 上下文参数
}
```

#### 2.2.2 Skills与RAG集成接口

```java
/**
 * Skills知识加载器
 * 负责从Skill包中加载知识文档
 */
public interface SkillsKnowledgeLoader {
    
    /**

     * 加载来源：
     * 1. Skill元数据中的knowledgeDocuments

/**
 * RAG管道接口
 * 负责检索增强生成
 */
public interface RagPipeline {

     * 检索相关知识

    RagResult retrieve(RagContext context);

     * 增强提示

    String augmentPrompt(String query, RagResult result);
    
    /**
     * 生成回答
     */
    String generate(String query, RagContext context);
}
```

## 三、嵌入设计模式

### 3.1 三种嵌入模式

```
┌─────────────────────────────────────────────────────────────────────────┐
│                      LLM Skills 嵌入模式对比                             │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  模式1: 直接嵌入 (Direct Embedding)                                      │
│  ────────────────────────────────────────────────────────────────────   │
│                                                                         │

│              │                                                          │

│                                                                         │

│                                                                         │
│  ────────────────────────────────────────────────────────────────────   │
│                                                                         │
│  模式2: RAG增强嵌入 (RAG-Augmented Embedding)                            │
│  ────────────────────────────────────────────────────────────────────   │
│                                                                         │
│  User ──▶ LLM ──▶ RAG Retrieval ──▶ Skill Execution ──▶ Result          │
│              │         │                                                │
│              │         └── 检索相关知识                                   │
│              └── 生成检索查询                                             │
│                                                                         │
│  适用场景: 知识密集型任务、问答场景                                         │
│  优点: 回答准确、可解释性强                                                │
│  缺点: 增加检索延迟、需要维护知识库                                          │
│                                                                         │
│  ────────────────────────────────────────────────────────────────────   │
│                                                                         │
│  模式3: 场景编排嵌入 (Scene Orchestrated Embedding)                      │
│  ────────────────────────────────────────────────────────────────────   │
│                                                                         │
│  User ──▶ Scene Engine ──▶ Context Assembly ──▶ LLM ──▶ Skill Chain     │
│                               │                              │          │
│                               │                              └── 多Skill协作
│                               └── 组装完整上下文                                            │
│                                                                         │
│  适用场景: 复杂业务流程、多Skill协作场景                                     │
│  优点: 支持复杂流程、上下文连贯、可观测性强                                   │
│  缺点: 架构复杂、需要场景编排能力                                            │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## 四、关键设计决策

### 4.1 决策1: 向量化能力归属

**问题**: 向量化应该放在哪一层？

**决策**: 向量化是LLM的核心能力，属于模型服务层

```
┌─────────────────────────────────────────┐
│ ✅ 正确设计                              │
├─────────────────────────────────────────┤
│ LLM Service                             │
│ ├── chat()                              │
│ ├── embed()  ◄── 向量化作为LLM能力        │
│ └── functionCall()                      │
└─────────────────────────────────────────┘

┌─────────────────────────────────────────┐
│ ❌ 错误设计                              │
├─────────────────────────────────────────┤
│ Embedding Service (独立服务)             │
│ └── embed()                             │
│                                         │
│ LLM Service                             │
│ └── chat()                              │
└─────────────────────────────────────────┘
```

**理由**:
1. 向量化模型是LLM的一部分（如 text-embedding-ada-002）
2. 不同LLM提供者的向量化接口不同，需要适配
3. 向量化结果与LLM的对话模型配套使用效果更好

### 4.2 决策2: 知识库与向量库的关系

**问题**: 知识库和向量库是否重复？

**决策**: 两者职责不同，互补关系

```
┌─────────────────────────────────────────────────────────┐
│                    知识库与向量库关系                      │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  ┌─────────────────┐  ┌─────────────────┐  ┌──────────┐ │
│  │  KnowledgeBase  │  │   VectorStore   │  │ Document │ │
│  │                 │  │                 │  │  Store   │ │
│  │ • 文档管理       │  │ • 向量索引       │  │ • 原文存储│ │
│  │ • 元数据管理     │  │ • 相似度检索     │  │ • 分块存储│ │
│  │ • 权限管理       │  │ • 元数据过滤     │  │ • 版本管理│ │
│  └────────┬────────┘  └────────┬────────┘  └────┬─────┘ │
│           │                    │                 │       │
│           └────────────────────┴─────────────────┘       │
│                              │                          │
│                              ▼                          │
│                    ┌─────────────────┐                  │
│                    │   RAG Pipeline  │                  │
│                    │                 │                  │
│                    │ Query → Embed → │                  │
│                    │ Retrieve → Augment                  │
│                    └─────────────────┘                  │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

**数据流**:
```
文档入库:
Document ──▶ KnowledgeBase.addDocument()
                  │
                  ├──▶ DocumentStore.save() (存储原文)
                  │
                  └──▶ Chunking ──▶ LLM.embed() ──▶ VectorStore.insert()

检索:
Query ──▶ LLM.embed() ──▶ VectorStore.search() ──▶ KnowledgeBase.getDocuments()
```

### 4.3 决策3: Skills调用方式

**问题**: Skills如何与LLM交互？

**决策**: 通过Function Calling机制

```
┌─────────────────────────────────────────────────────────┐
│                   Function Calling Flow                  │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. User Query                                          │
│       │                                                 │
│       ▼                                                 │
│  2. LLM Analysis ──▶ Tool Selection                     │
│       │                                                 │
│       ▼                                                 │
│  3. Tool Execution ──▶ Skill Execution                  │
│       │                    │                            │
│       │                    ├──▶ RAG.retrieve()          │
│       │                    ├──▶ Database.query()        │
│       │                    └──▶ API.call()              │
│       │                                                 │
│       ▼                                                 │
│  4. Result Return ──▶ LLM Generation                    │
│       │                                                 │
│       ▼                                                 │
│  5. Final Response                                      │
│                                                         │
└─────────────────────────────────────────────────────────┘
```
