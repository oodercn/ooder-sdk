## 一、设计目标

### 1.1 三大闭环

| 闭环 | 目标 | 检验标准 |
|------|------|----------|
| **数据闭环** | 知识库、LLM配置齐全，所有实例地址明确 | 所有能力地址可解析，配置可追溯 |
| **用户界面闭环** | 用户操作流程完整，界面交互清晰 | 用户可完成完整安装-激活-使用流程 |
| **用户故事闭环** | 业务需求完整实现，角色权限正确 | 所有用户故事验收通过 |

### 1.2 核心设计原则

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                     3.0 核心设计原则                                          │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  1. 能力地址固定                                                            │
│     • 128个固定地址 (0x00-0x7F)                                             │
│     • 16个分类 × 8个地址                                                    │
│     • 编译时确定，运行时不变                                                 │
│                                                                             │
│  2. 配置分层管理                                                            │
│     • MCP层：预定义配置，手动优先                                            │
│     • ROUTE层：动态配置，自动原则                                            │
│                                                                             │
│  3. 上下文隔离                                                              │
│     • 同一地址多实例通过contextId区分                                        │
│     • userSessionId/agentSessionId作为安全标识                              │
│                                                                             │
│  4. 用户参与明确                                                            │
│     • 自动任务：后台完成，无需用户干预                                        │
│     • 手动任务：需要用户界面交互确认                                          │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 二、数据闭环设计

### 2.1 能力地址分配

#### 2.1.1 固定地址区 (0x00-0x7F)

| 分类 | 地址范围 | 用途 | 场景技能依赖 |
|------|----------|------|-------------|
| **SYS** | 0x00-0x07 | 系统核心 | 所有场景 |
| **ORG** | 0x08-0x0F | 组织服务 | TBS场景必需 |
| **AUTH** | 0x10-0x17 | 认证服务 | 所有场景 |
| **VFS** | 0x18-0x1F | 文件存储 | 文档类场景 |
| **DB** | 0x20-0x27 | 数据库 | 所有场景 |
| **LLM** | 0x28-0x2F | 大语言模型 | LLM场景必需 |
| **KNOW** | 0x30-0x37 | 知识库 | RAG场景必需 |
| **PAY** | 0x38-0x3F | 支付服务 | 支付场景 |
| **MEDIA** | 0x40-0x47 | 媒体服务 | 媒体场景 |
| **COMM** | 0x48-0x4F | 通讯服务 | 通知场景 |
| **MON** | 0x50-0x57 | 监控服务 | 运维场景 |
| **IOT** | 0x58-0x5F | 物联网 | IoT场景 |
| **SEARCH** | 0x60-0x67 | 搜索服务 | 搜索场景 |
| **SCHED** | 0x68-0x6F | 调度服务 | 定时任务场景 |
| **SEC** | 0x70-0x77 | 安全服务 | 所有场景 |
| **NET** | 0x78-0x7F | 网络服务 | 代理场景 |

### 2.3 配置数据结构

#### 2.3.1 技能元数据 (skill.yaml)

```yaml
apiVersion: skill.ooder.net/v1
kind: Skill

metadata:
  id: skill-daily-report
  name: 日志汇报
  version: 3.0.0
  category: business          # 分类: business/infrastructure/ai
  sceneType: daily-report     # 场景类型
  skillType: tbs              # 技能类型: abs/tbs/ass

spec:
  # 能力地址依赖
  capabilityAddresses:
    required:
      - address: 0x08         # ORG_LOCAL
        name: "组织服务"
        fallback: null        # 必需，无降级
      - address: 0x20         # DB_SQLITE
        name: "数据存储"
        fallback: 0x21        # 降级到MySQL
      - address: 0x28         # LLM_OLLAMA
        name: "LLM服务"
        fallback: 0x29        # 降级到OpenAI
    optional:
      - address: 0x4A         # COMM_EMAIL
        name: "邮件服务"
        skipable: true

  # 角色配置
  roles:
    - name: MANAGER
      displayName: "管理者"
      minCount: 1
      maxCount: 1
      permissions: [READ, WRITE, CONFIG, DELETE]
    - name: EMPLOYEE
      displayName: "员工"
      minCount: 1
      maxCount: 100
      permissions: [READ, WRITE]

  # 激活流程
  activationSteps:
    MANAGER:
      - stepId: select-participants
        type: USER_SELECT     # 需要用户界面
        required: true
      - stepId: config-llm
        type: CONFIG_FORM     # 需要用户界面
        required: false
        skipable: true
      - stepId: bind-addresses
        type: AUTO            # 自动完成
        required: true
    EMPLOYEE:
      - stepId: accept-invite
        type: CONFIRM         # 需要用户确认
        required: true
```

#### 2.3.2 激活配置 (ActivationConfig)

```java
public class ActivationConfig {
    private String skillId;
    private String sceneGroupId;
    private String userId;
    private String userSessionId;      // 安全标识1
    private String agentSessionId;     // 安全标识2
    
    // 能力地址绑定
    private Map<Integer, String> addressBindings;  // address → providerId
    
    // 角色配置
    private String role;
    private List<String> permissions;
    
    // LLM配置
    private LlmConfig llmConfig;
    
    // 知识库配置
    private List<String> knowledgeBaseIds;
}
```

### 2.4 数据检验标准

| 检验项 | 检验方法 | 预期结果 |
|--------|----------|----------|
| 能力地址可解析 | `CapabilityAddress.fromAddress(addr)` | 返回有效枚举 |
| Provider可用 | `router.getDriver(address)` | 返回非null |
| 配置完整性 | 检查required字段 | 100%填充 |
| 安全标识有效 | userSessionId/agentSessionId非空 | 验证通过 |
