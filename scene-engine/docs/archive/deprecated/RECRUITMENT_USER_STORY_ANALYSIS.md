## 一、招聘场景概述

### 1.1 业务流程

```
发布职位 → 简历筛选 → 面试安排 → 面试评估 → 发放Offer
```

### 1.2 业务痛点

| 痛点 | 描述 | 影响 |
|------|------|------|
| 简历筛选效率低 | HR每天需处理数百份简历 | 人力成本高、响应慢 |
| 面试安排复杂 | 协调候选人、面试官、会议室 | 沟通成本高、易出错 |
| 评估标准不统一 | 主观因素影响招聘质量 | 招聘质量不稳定 |
| 流程跟踪困难 | 无法实时了解招聘进度 | 管理效率低 |

## 二、知识库在招聘场景中的作用

### 2.1 三层知识架构

| 层级 | 知识内容 | 招聘场景示例 |
|------|----------|--------------|
| **通用知识层** | 公司制度、流程规范 | 招聘政策、薪酬标准、入职流程 |
| **专业模块层** | 领域专业知识 | 岗位要求、面试题库、技能标准 |
| **场景知识层** | 场景私有知识 | 候选人简历、面试记录、评价结果 |

### 2.2 知识库服务模式

#### 模式1: 为LLM服务（RAG增强）

```
用户查询 ──▶ LLM ──▶ 知识检索 ──▶ 增强回答
```

**价值**：
- 增强LLM的领域知识
- 提供上下文信息
- 减少幻觉

**招聘场景示例**：
```
用户: "Java开发岗位的技能要求是什么？"
LLM: 从岗位要求库检索 → "根据岗位要求库，Java开发需要：
     1. 3年以上Java开发经验
     2. 熟悉Spring框架
     3. 了解MySQL数据库..."
```

#### 模式2: 为用户服务（直接检索）

```
用户查询 ──▶ 知识检索 ──▶ 直接返回结果
```

**价值**：
- 直接提供信息
- 可追溯来源
- 无需LLM参与

**招聘场景示例**：
```
用户: "查看张三的简历"
系统: 从候选人库检索 → 返回简历详情页
```

### 2.3 招聘场景知识库应用

| 知识库 | 内容 | 服务对象 | 用途 |
|--------|------|----------|------|
| **公司制度库** | 招聘政策、薪酬标准、入职流程 | LLM | 回答政策问题 |
| **岗位要求库** | 职位描述、技能要求、面试题库 | 用户 + LLM | 筛选和面试 |
| **候选人库** | 简历数据、面试记录、评价结果 | Capability | 筛选和评估 |

### 2.4 知识库与Capability关系

```
Capability: resume_screening (简历筛选)
    │
    ├── 知识依赖:
    │   ├── KB: 岗位要求库 ──▶ 获取筛选标准
    │   └── KB: 候选人库 ──▶ 获取简历数据
    │
    └── 执行流程:
        1. 从岗位要求库获取筛选条件
        2. 从候选人库检索匹配简历
        3. (可选) LLM辅助评估
        4. 返回筛选结果
```

## 三、LLM在招聘场景中的作用

### 3.1 LLM三种介入模式

#### 模式1: LLM作为路由器

**适用场景**：用户意图不明确，需要LLM理解并路由

```
用户: "帮我预约面试"
LLM分析:
  - 意图: 面试安排
  - Capability: interview_schedule
  - 参数: 需要进一步询问时间、候选人
```

#### 模式2: LLM作为执行器

**适用场景**：需要LLM生成内容或处理自然语言

```
用户: "生成面试邀请邮件"
LLM执行:
  - 输入: 候选人信息、面试时间
  - 输出: 格式化的邮件内容
```

#### 模式3: LLM作为协调器

**适用场景**：复杂任务需要多步骤协调

```
用户: "帮我完成招聘流程"
LLM协调:
  Step 1: 收集简历 (Capability A)
  Step 2: 筛选简历 (Capability B)
  Step 3: 安排面试 (Capability C)
  Step 4: 发送通知 (Capability D)
```

### 3.2 招聘场景完整示例

```
用户: "帮我筛选一下今天收到的简历，找出符合条件的"

Step 1: 意图理解 (LLM Router)
────────────────────────────────
LLM分析:
- 意图: 简历筛选
- 时间范围: 今天
- 条件: 需要进一步询问

Step 2: 参数收集 (LLM Router)
────────────────────────────────
LLM反问: "请问筛选条件是什么？"
用户: "3年以上Java经验，本科以上学历"
LLM提取:
- 经验要求: 3年以上
- 技能要求: Java
- 学历要求: 本科及以上

Step 3: 能力调用 (Capability)
────────────────────────────────
调用 Capability: resume_screening
参数: {
  "dateRange": "today",
  "experience": "3+",
  "skills": ["Java"],
  "education": "bachelor+"
}

Step 4: 结果生成 (LLM Executor)
────────────────────────────────
Capability返回: 5份符合条件的简历
LLM生成:
"今天收到20份简历，筛选出5份符合条件的：
 1. 张三 - 5年Java经验，硕士
 2. 李四 - 4年Java经验，本科
 ..."
```

### 3.3 LLM工作模式

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| **OFFLINE** | 完全离线，仅依赖规则库 | LLM不可用、数据安全要求高 |
| **DEGRADED** | 规则库优先，LLM增强 | 成本控制、性能优化 |
| **ONLINE** | LLM主导，规则库辅助 | 智能决策、复杂任务 |

## 六、价值总结

### 6.1 知识库价值

| 价值维度 | 说明 |
|----------|------|
| **数据沉淀** | 招聘过程中的知识资产得以保存和复用 |
| **标准化** | 岗位要求、评估标准统一，提高招聘质量 |
| **可追溯** | 招聘决策有据可查，便于审计 |
| **知识共享** | 团队知识共享，降低人员流动影响 |

### 6.2 LLM价值

| 价值维度 | 说明 |
|----------|------|
| **效率提升** | 自动化处理重复性工作，如简历筛选、通知生成 |
| **体验优化** | 自然语言交互，降低使用门槛 |
| **智能决策** | 意图理解、参数提取、结果生成 |
| **降级保障** | 离线规则引擎保证基本功能可用 |

### 6.3 协同价值

| 价值维度 | 说明 |
|----------|------|
| **RAG增强** | LLM结合知识库，提供准确的领域回答 |
| **闭环优化** | 用户反馈 → LLM生成规则 → 知识库更新 |
| **弹性架构** | 在线/离线切换，适应不同场景需求 |

```java
KnowledgeCapability knowledgeCap = new KnowledgeCapabilityImpl(
    embeddingService, vectorStore, knowledgeBaseService
);

KnowledgeResult result = knowledgeCap.retrieveCrossLayer(
    "Java开发岗位要求", 
    KnowledgeLayer.SCENE
```

### 7.2 LLM决策实现

```java
DecisionEngine engine = new DecisionEngineImpl(llmProvider, ruleEngine);
engine.setMode(DecisionMode.ONLINE_FIRST);

DecisionContext context = DecisionContext.builder()
    .query("帮我筛选今天的简历")
    .userId("hr-001")
    .param("department", "HR")
    .build();

DecisionResult result = engine.decide(context);
```

### 7.3 离线降级实现

```java
private DecisionResult decideWithFallback(DecisionContext context) {
    if (llmProvider != null && llmProvider.isAvailable()) {
        try {
            return decideWithLlm(context);
        } catch (Exception e) {
            log.warn("LLM decision failed, fallback to rule engine");
        }
    }
    return decideWithRules(context);
}
```

## 八、结论

在招聘场景中，**知识库**和**LLM**形成了互补协同关系：

1. **知识库**提供结构化的领域知识，是系统的"记忆"
2. **LLM**提供智能的理解和生成能力，是系统的"大脑"
3. **协同工作**实现智能招聘，提升效率和体验
4. **降级策略**保证系统在LLM不可用时仍能提供基本服务

这种架构设计使得招聘系统既具备智能化的交互体验，又具备稳定可靠的数据支撑能力。
